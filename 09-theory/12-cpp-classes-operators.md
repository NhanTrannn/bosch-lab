# Classes, operator overloading, inheritance, polymorphism

## Theory

Follows the Udemy course *Beginning C++ Programming*, sections 13–16. Labs: `02-cpp/23` … `02-cpp/25`; see also `02-cpp/01` … `05`, `09`, `10`, `12`, `13`. The "Object-oriented C++" topic above has a shorter summary.

### Classes and objects (section 13)
- A class is a blueprint (a user-defined type); an object is an instance of the class.
- Access specifiers: `public` (everywhere), `private` (only the class and its friends), `protected` (also derived classes). `class` defaults to private, `struct` to public; otherwise the two keywords are identical.
- **Encapsulation**: data is private and accessed through getters/setters that keep values valid.
- Member functions defined inside the class are implicitly `inline`. Defined outside: `void Player::talk() {...}`. Usually the class is declared in a `.h` (with an include guard `#ifndef/#define/#endif` or `#pragma once`) and defined in a `.cpp`.
- **Constructor**: same name as the class, no return type, can be overloaded. **Destructor** `~T()`: no parameters, no overloads, called automatically when the object goes out of scope or is `delete`d.
- The **default constructor** (no parameters) is generated by the compiler only when the class has **no constructors at all**. Once you write `Player(string)`, `Player p;` is an error unless you add `Player() = default;`.
- **Initializer list** `T() : a{1}, b{2} {}`: initializes directly instead of assigning later. Members are initialized in **declaration order**, not list order. Required for `const` members, references, and members/bases without a default constructor.
- **Delegating constructor** (C++11): `Player() : Player{"None", 0, 0} {}`. The target constructor runs completely (including its body) before the delegating constructor's body. It cannot also initialize other members in the same list.
- Default arguments on constructors reduce the number of overloads; watch out for ambiguity with the default constructor.
- **Copy constructor** `T(const T &src)`: called when initializing from an object of the same type (`T b = a;`, `T b(a);`), passing by value, returning by value (may be skipped by copy elision). The parameter must be a reference, otherwise infinite recursion.
- **Shallow copy** (default): copies each member; a pointer only copies the address → two objects point to the same memory → double free when both destructors delete it. **Deep copy**: allocate new memory and copy the data.
- **Move constructor** `T(T &&src) noexcept`: "steals" the resources of a temporary (copy the pointer, then set the source pointer to nullptr) without allocating. Called when the source is an rvalue or `std::move(x)`.
- `this`: a pointer to the current object. Used when a parameter has the same name as a member (`this->name = name`), to return `*this` for chaining, and to check self-assignment `if (this == &rhs)`.
- A **const object** can only call **const member functions** `int get() const;`. Inside a const function, `this` has type `const T*`. `mutable` members can still be modified.
- **static member**: shared by all objects of the class; must be defined once outside the class (`int Player::count = 0;`) or declared `inline static` (C++17). A **static member function** has no `this`, can only access static members, and is called as `Player::get_count()`.
- **friend**: an outside function/class may access private members. Friendship is not symmetric, not transitive and not inherited.
- `struct` vs `class`: by convention, struct for plain data (public), class for objects with invariants and encapsulation.

### Operator overloading (section 14)
- Member syntax `T operator+(const T &rhs) const;` (the left operand is `*this`) or non-member `T operator+(const T &lhs, const T &rhs);`.
- **Cannot** be overloaded: `::` `.` `.*` `?:` `sizeof` (and `typeid`, `alignof`). You cannot create new operators or change precedence, associativity or arity. At least one operand must be a user-defined type.
- Must be members: `=` `[]` `()` `->` and conversion operators.
- Must be non-members when the left operand is not your class: `ostream &operator<<(ostream &os, const T &obj)` (returns `os` for chaining), `T operator*(int, const T&)`. Usually declared as friends.
- **Copy assignment** `T &operator=(const T &rhs)`: check for self-assignment, release the old resource, deep copy, `return *this`. **Move assignment** `T &operator=(T &&rhs) noexcept`.
- Note: `T b = a;` calls the copy **constructor**; `b = a;` (b already exists) calls copy **assignment**.
- Prefix `T &operator++()` returns `*this`; postfix `T operator++(int)` (dummy int parameter) returns a copy of the old value.
- Unary `-` and `!` are members without parameters. Comparisons `==`, `<` usually return `bool`. C++20: `operator<=>` generates the comparison operators.
- A single-argument constructor without `explicit` is an **implicit conversion**: `Vec v = 5;`. Add `explicit` to block it.

### Inheritance (section 15)
- An **is-a** relationship (Savings is-a Account) → inheritance. **has-a** (Player has-a Weapon) → composition (a member).
- `class Derived : public Base`. Inheritance kinds (default `private` for class, `public` for struct):

| Member in Base | public inheritance | protected inheritance | private inheritance |
| --- | --- | --- | --- |
| public | public | protected | private |
| protected | protected | protected | private |
| private | not accessible | not accessible | not accessible |

- Only public inheritance models a true is-a relationship (a Base* can point to a Derived).
- A derived class does **not inherit**: constructors, destructor, copy/move assignment, friends. C++11: `using Base::Base;` reuses the base constructors.
- Order: Base constructor → Derived's members → Derived constructor body. Destructors run in reverse. Calling a Base constructor with arguments: `Derived(int x) : Base{x}, ... {}`; otherwise Base's default constructor is called.
- A hand-written copy constructor/operator= in Derived must call Base's: `Derived(const Derived &d) : Base{d} {...}`, `Base::operator=(rhs);`. If you forget, the Base part is default-constructed (constructor) or left unchanged (operator=).
- **Redefining** a function (same signature, not virtual) → static binding: chosen by the static type of the variable/pointer. Call the base version: `Base::f()`.
- A function with the same name in Derived **hides** all base overloads with that name → `using Base::f;`.
- Multiple inheritance: `class C : public A, public B`. Diamond → `virtual` inheritance.

### Polymorphism (section 16)
- **Compile-time (static) polymorphism**: function overloading, operator overloading, templates. **Run-time (dynamic) polymorphism**: virtual functions called through a pointer/reference to Base.
- `virtual` in Base → the matching function in every derived class is virtual (whether or not it repeats the keyword). Calling through an object (not a pointer/reference) is always static binding.
- Mechanism: each class with virtual functions has a **vtable** (table of function pointers); each object has a **vptr** pointing to its real class's vtable → `sizeof` grows by 8 bytes.
- **Virtual destructor**: a Base used polymorphically needs `virtual ~Base()`, otherwise `delete basePtr` is UB (usually only `~Base` runs).
- `override` (C++11): an error if the function does not actually override (wrong signature, missing const, Base not virtual). `final`: forbids further overriding (on a function) or inheritance (on a class).
- Calls through a Base **reference** are just as polymorphic as through a pointer.
- **Pure virtual** `virtual void draw() = 0;` → the class is **abstract**: you cannot create objects of it, but you can declare pointers/references to it. A derived class that does not override every pure virtual function is still abstract.
- **Interface**: an abstract class with only pure virtual functions (plus a virtual destructor) and no data. E.g. `I_Printable` with `virtual void print(ostream&) const = 0;`, and an `operator<<` that calls `obj.print(os)` → one `operator<<` for every derived class.
- **Object slicing**: assigning/passing a Derived by value into a Base → the Derived part is lost, and so is polymorphism. Store polymorphic objects in containers as `vector<Base*>` or `vector<unique_ptr<Base>>`.
- Default arguments of virtual functions come from the **static type** (lab `02-cpp/10`). A virtual call inside a constructor/destructor runs the version of the class being built (lab `02-cpp/04`).

## Quiz

### What is the ONLY difference between `struct` and `class` in C++?
- [ ] structs have no member functions
- [ ] structs cannot be inherited from
- [x] The default access (for members and inheritance): public for struct, private for class
- [ ] structs live on the stack, classes on the heap
> Apart from the default access, the two keywords have exactly the same capabilities.

### What is wrong with this code?
```cpp
class Player {
    std::string name;
public:
    Player(std::string n) : name{n} {}
};
int main() { Player p; }
```
- [ ] Nothing
- [x] Compile error: there is no default constructor
- [ ] Linker error
- [ ] name is uninitialized
> The compiler only generates a default constructor when the class declares no constructors. Fix with `Player() = default;` or a default argument.

### What does this print?
```cpp
struct P {
    P() : P{0} { cout << "A"; }
    P(int) { cout << "B"; }
};
int main() { P p; }
```
- [ ] A
- [ ] AB
- [x] BA
- [ ] B
> Delegating constructor: the target constructor `P(int)` finishes first, then the body of `P()` runs.

### Which members MUST be initialized in the initializer list? (select all that apply)
- [x] A `const int` member
- [x] A reference member `int&`
- [x] A member object of a class without a default constructor
- [ ] A `std::string` member
> These three cannot be "created first and assigned later". `std::string` has a default constructor, so assigning in the body also works (just less efficiently).

### How many times is the copy constructor called (ignoring copy elision)?
```cpp
void show(Player p);
Player a{"A"};
Player b = a;
show(b);
b = a;
```
- [ ] 1
- [x] 2
- [ ] 3
- [ ] 0
> `Player b = a` and passing by value to `show` call the copy constructor. `b = a` (b already exists) calls copy assignment.

### Why must the copy constructor take `const T&` rather than `T`?
- [ ] To be faster
- [x] Passing by value would itself need the copy constructor → infinite recursion (the compiler rejects it)
- [ ] The standard requires every parameter to be a reference
- [ ] So the source object cannot be modified
> `const` lets it accept const objects and temporaries; the reference is what avoids the recursion.

### A class has an `int *data` member allocated with new and uses the default copy constructor. An object is copied, then both are destroyed (the destructor deletes data). Result?
- [ ] Works fine
- [ ] A memory leak
- [x] A double free (undefined behavior, usually a crash)
- [ ] Compile error
> The shallow copy makes both objects hold the same address. You need a deep copy (rule of three) or `unique_ptr`/`vector`.

### What does a move constructor usually do?
- [ ] Deep-copies the data into the new object
- [x] Takes the source's resource pointer, then sets the source pointer to nullptr
- [ ] Deletes the source object
- [ ] Calls the copy constructor
> No new allocation, so it is cheap. The source must be left valid so its destructor still runs safely.

### What does `get_name()` need so it can be called on `const Player p`?
- [ ] It must be static
- [x] It must be declared `const`: `std::string get_name() const;`
- [ ] It must be a friend
- [ ] It must return const
> A const object can only call const member functions, because its `this` has type `const Player*`.

### Which statement about static member functions is TRUE?
- [ ] They have a this pointer
- [ ] They can access every normal member
- [x] They have no this, can directly access only static members, and can be called as `Class::f()` without an object
- [ ] They cannot be called through an object
> Calling through an object (`p.f()`) is allowed, but there is still no this.

### A static data member `static int count;` declared in a class (before C++17) also needs:
- [ ] Nothing
- [x] Exactly one definition in a .cpp file: `int Player::count = 0;`
- [ ] Initialization in the constructor
- [ ] An extern declaration
> Without the definition, using it gives a linker "undefined reference". In C++17 you can write `inline static int count = 0;` inside the class.

### Which operators can NOT be overloaded? (select all that apply)
- [x] `::`
- [x] `?:`
- [ ] `[]`
- [x] `.`
> You cannot overload `::`, `.`, `.*`, `?:`, `sizeof`. `[]` can be overloaded (and must be a member).

### Why must `operator<<` for `cout << obj` be a non-member function?
- [ ] Member functions cannot return references
- [x] The left operand is a `std::ostream`, not your class
- [ ] `<<` is a unary operator
- [ ] Friends are faster
> For members, the left operand is always `*this`. As a member you would have to write `obj << cout`.

### What is the correct signature for postfix `++`?
- [ ] `T &operator++();`
- [x] `T operator++(int);`
- [ ] `T &operator++(int);`
- [ ] `T operator++(T);`
> The dummy `int` parameter distinguishes it from prefix. Postfix returns a copy of the old value, so it returns by value.

### What should the copy assignment operator return?
- [ ] void
- [ ] T by value
- [x] `T&` (`*this`)
- [ ] `const T*`
> Returning `*this` allows chaining `a = b = c` like built-in types and avoids an extra copy.

### Why does copy assignment check `if (this == &rhs) return *this;`?
- [ ] For speed
- [x] Self-assignment `a = a` would free the resource and then copy from the memory it just freed
- [ ] The standard requires it
- [ ] To avoid calling the destructor
> An alternative is the copy-and-swap idiom: safe for self-assignment and with exceptions.

### When does `Vec v = 5;` compile?
- [ ] Never
- [x] When Vec has a constructor taking one int that is not `explicit`
- [ ] When Vec overloads `operator=` taking an int
- [ ] When Vec has `operator int()`
> A non-explicit single-argument constructor is an implicit conversion. With `explicit` you must write `Vec v{5};`.

### With public inheritance, what does a `protected` member of Base become in Derived?
- [ ] public
- [x] protected
- [ ] private
- [ ] Not accessible
> Public inheritance keeps public → public and protected → protected. Base's private members are never directly accessible from Derived.

### In what order are constructors called for `C c;` with `class C : public B` and `class B : public A`?
- [ ] C, B, A
- [x] A, B, C
- [ ] B, A, C
- [ ] Only C
> Constructors go from the root base downwards. Destructors go the other way: C, B, A.

### What does a derived class NOT inherit from its base? (select all that apply)
- [x] Constructors
- [x] The destructor
- [x] The copy assignment operator
- [ ] Ordinary public member functions
> To reuse the base constructors, write `using Base::Base;` (C++11).

### `Account::withdraw` is NOT virtual and `Savings` redefines it. Which version does this call?
```cpp
Savings s;
Account &ref = s;
ref.withdraw(100);
```
- [x] `Account::withdraw`
- [ ] `Savings::withdraw`
- [ ] Compile error
- [ ] Ambiguous
> Not virtual → static binding on ref's type (`Account&`). With virtual it would call `Savings::withdraw`.

### Inside a derived class, how do you call the base class's `display()`?
- [ ] `super.display()`
- [ ] `base->display()`
- [x] `Base::display()`
- [ ] `this->Base.display()`
> C++ has no `super` keyword; use the scope operator with the base class name.

### Derived's hand-written copy constructor does not call `Base{other}` in its initializer list. How is the Base part of the copy built?
- [ ] Copied from other
- [x] With Base's default constructor
- [ ] Left uninitialized
- [ ] Compile error
> The Base part is not copied → a silent bug. Write `Derived(const Derived &d) : Base{d}, ...`.

### Which are compile-time (static) polymorphism? (select all that apply)
- [x] Function overloading
- [x] Operator overloading
- [x] Templates
- [ ] Calling a virtual function through a Base pointer
> Virtual functions through a pointer/reference are run-time polymorphism (dynamic binding via the vtable).

### What does the `override` keyword do?
- [ ] Makes the base function virtual
- [x] Makes the compiler report an error if the function does not actually override a virtual function of the base
- [ ] Makes the function faster
- [ ] Forbids derived classes from overriding further
> It catches wrong signatures (missing const, different parameter types) that would otherwise silently create a new function. Forbidding further overrides is `final`'s job.

### A class has `virtual void draw() = 0;`. What follows?
- [ ] Nothing special
- [x] It is an abstract class: no objects can be created, but pointers/references can be declared
- [ ] No class can derive from it
- [ ] Compile error because the function has no body
> A derived class must override every pure virtual function before objects can be created (a concrete class).

### What does `final` after a class name (`class Trust final : public Savings`) mean?
- [ ] No objects can be created
- [x] No class can derive from Trust
- [ ] Every function of Trust is virtual
- [ ] Trust is abstract
> `final` after a single virtual function forbids derived classes from overriding just that function.

### What does this print? (`speak` is virtual)
```cpp
vector<Animal> zoo;
zoo.push_back(Dog{});
zoo[0].speak();
```
- [ ] Dog::speak
- [x] Animal::speak
- [ ] Compile error
- [ ] Undefined behavior
> `vector<Animal>` stores by value → the Dog is sliced into an Animal. For polymorphism use `vector<unique_ptr<Animal>>` or `vector<Animal*>`.

### How much extra memory does each object of a class with virtual functions take (x86-64, single inheritance)?
- [ ] One pointer per virtual function
- [x] One vptr (8 bytes, plus possible padding)
- [ ] Nothing extra
- [ ] A whole vtable
> The vtable is shared by the whole class; each object only holds a vptr to it.
