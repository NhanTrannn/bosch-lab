# C cơ bản

## Lý thuyết

### Kiểu dữ liệu và sizeof (x86_64 Linux, LP64)
| Kiểu | Byte | Ghi chú |
| --- | --- | --- |
| `char` | 1 | có dấu hay không là implementation-defined (x86: có dấu, ARM: thường không dấu) |
| `short` | 2 | |
| `int` | 4 | |
| `long` | 8 | Windows 64-bit (LLP64): 4 |
| `long long` | 8 | |
| `float` / `double` | 4 / 8 | |
| con trỏ bất kỳ | 8 | 4 trên hệ 32-bit |

- `sizeof` là **toán tử** tính lúc biên dịch (trừ VLA), trả `size_t`. `sizeof(arr)/sizeof(arr[0])` chỉ đúng với mảng thật, không đúng với tham số hàm.
- `uint8_t`, `int32_t`... trong `<stdint.h>` có kích thước cố định — luôn dùng trong embedded.

### Con trỏ
- `int *p[3]`: mảng 3 con trỏ. `int (*p)[3]`: con trỏ tới mảng 3 int. `int (*f)(int)`: con trỏ hàm. `int *f(int)`: hàm trả `int*`.
- `const int *p` / `int const *p`: không sửa được **giá trị** qua p. `int *const p`: không đổi được **p**. `const int *const p`: cả hai.
- `p + 1` tăng `sizeof(*p)` byte. Hiệu hai con trỏ tính theo số phần tử.
- `void *` không làm số học được (gcc cho phép như extension), phải ép kiểu trước khi dereference.
- Con trỏ treo (dangling): trỏ vào vùng đã free/biến local đã hết scope. Wild pointer: chưa khởi tạo. NULL pointer dereference → segfault.

### Bộ nhớ của chương trình
- **text**: mã lệnh (chỉ đọc). **rodata**: hằng, string literal. **data**: global/static có khởi tạo khác 0. **bss**: global/static không khởi tạo hoặc = 0 (tự về 0, không chiếm chỗ trong file). **heap**: malloc, tăng lên. **stack**: biến local, tham số, địa chỉ trả về, giảm xuống.
- `malloc` không khởi tạo; `calloc(n, size)` khởi tạo 0; `realloc` có thể di chuyển vùng nhớ (con trỏ cũ hết hợp lệ); `free(NULL)` hợp lệ; free hai lần → UB.
- Memory leak: mất con trỏ tới vùng malloc. Kiểm tra bằng `valgrind --leak-check=full`.

### static, extern, volatile, const
- `static` ở biến local: sống suốt chương trình, khởi tạo một lần. Ở biến/hàm mức file: **internal linkage** (chỉ thấy trong file đó).
- `extern`: khai báo biến được định nghĩa ở file khác (không cấp phát).
- `volatile`: báo compiler giá trị có thể đổi ngoài luồng chương trình (thanh ghi phần cứng, biến sửa trong ISR, memory-mapped I/O) → không tối ưu bỏ đọc/ghi. **Không** đảm bảo atomic hay đồng bộ giữa thread.
- `const volatile`: thanh ghi chỉ đọc của phần cứng (chương trình không ghi, nhưng giá trị vẫn tự đổi).
- `register`: gợi ý đặt trong thanh ghi; không lấy địa chỉ được.

### Preprocessor và macro
- Các bước: preprocess (`#include`, `#define`, `#if`) → compile → assemble → link.
- Macro thay thế văn bản: luôn bọc ngoặc tham số và toàn bộ biểu thức; tham số có thể bị tính nhiều lần (`MAX(i++, j)`). Macro nhiều lệnh bọc trong `do { ... } while (0)`.
- `#` biến tham số thành chuỗi, `##` nối token. `__FILE__`, `__LINE__`, `__func__`.
- Include guard `#ifndef X_H / #define X_H / #endif` hoặc `#pragma once`.
- `inline` function an toàn hơn macro (kiểm tra kiểu, tính tham số một lần).

### Struct, union, bit-field, endianness
- Padding: mỗi member căn theo alignment của nó; sizeof struct là bội của alignment lớn nhất. `#pragma pack(1)` / `__attribute__((packed))` bỏ padding.
- `union`: các member dùng chung vùng nhớ, sizeof = member lớn nhất (cộng padding).
- Bit-field `unsigned flag : 1;` — thứ tự bit và padding là implementation-defined, không lấy được địa chỉ.
- Little-endian (x86, phần lớn ARM): byte thấp ở địa chỉ thấp. Big-endian: network byte order. Đổi bằng `htonl/ntohl/htons/ntohs`.

### Undefined behavior hay gặp
Tràn số có dấu, chia cho 0, dereference NULL/con trỏ treo, truy cập ngoài mảng, đọc biến chưa khởi tạo, sửa string literal, `i = i++ + ++i` (sửa một biến hai lần không có sequence point), dịch bit ≥ độ rộng kiểu hoặc dịch trái số âm, free hai lần.

## Trắc nghiệm

### Trên Linux x86_64, `sizeof(long)` và `sizeof(void *)` lần lượt là?
- [ ] 4 và 4
- [ ] 4 và 8
- [x] 8 và 8
- [ ] 8 và 4
> Linux 64-bit dùng mô hình LP64: long và con trỏ đều 8 byte. Windows 64-bit dùng LLP64 nên long vẫn là 4.

### `sizeof(struct S)` bằng bao nhiêu trên x86_64?
```c
struct S { char a; int b; char c; };
```
- [ ] 6
- [ ] 8
- [x] 12
- [ ] 16
> a ở 0, 3 byte padding, b ở 4, c ở 8, rồi 3 byte padding cuối để tổng là bội của 4 → 12. Đổi thứ tự thành int, char, char thì còn 8.

### Khai báo `int (*p)[10];` nghĩa là gì?
- [ ] Mảng 10 con trỏ tới int
- [x] Con trỏ tới một mảng 10 int
- [ ] Hàm trả về con trỏ tới int
- [ ] Con trỏ tới hàm nhận 10 int
> Ngoặc làm `*p` gắn trước: p là con trỏ, trỏ tới `int[10]`. Không có ngoặc, `int *p[10]` là mảng 10 con trỏ.

### Với `const int *p;` câu nào đúng?
- [ ] Không thể cho p trỏ sang biến khác
- [x] Không thể sửa giá trị qua `*p`, nhưng có thể đổi p
- [ ] Không thể đổi cả p và `*p`
- [ ] Tương đương `int *const p`
> `const` đứng trước `*` áp lên dữ liệu được trỏ. `int *const p` mới là con trỏ hằng (không đổi được p).

### Biến toàn cục `int g;` không khởi tạo nằm ở vùng nhớ nào và có giá trị gì?
- [ ] stack, giá trị rác
- [ ] data, giá trị 0
- [x] bss, giá trị 0
- [ ] heap, giá trị rác
> Global/static không khởi tạo nằm ở .bss và được loader đặt về 0. .bss không chiếm chỗ trong file thực thi, chỉ ghi kích thước.

### `static` đặt trước một hàm ở mức file có tác dụng gì?
- [ ] Hàm chỉ được gọi một lần
- [ ] Hàm được nạp vào bộ nhớ tĩnh
- [x] Hàm chỉ thấy được trong file .c đó (internal linkage)
- [ ] Hàm trở thành inline
> static ở mức file giới hạn phạm vi liên kết trong translation unit đó, tránh trùng tên giữa các file.

### Khi nào bắt buộc nên dùng `volatile`? (chọn tất cả đáp án đúng)
- [x] Biến được sửa trong ISR và đọc ở vòng lặp chính
- [x] Con trỏ tới thanh ghi phần cứng memory-mapped
- [ ] Biến đếm dùng chung giữa nhiều thread để tránh race condition
- [ ] Biến hằng số cần đặt trong ROM
> volatile ngăn compiler bỏ qua hoặc cache việc đọc/ghi. Nó KHÔNG làm thao tác thành atomic và không thay được mutex/atomic giữa các thread.

### Kết quả của đoạn sau?
```c
#define SQ(x) x * x
int r = SQ(2 + 3);
```
- [ ] 25
- [x] 11
- [ ] 10
- [ ] Lỗi biên dịch
> Macro thay văn bản: `2 + 3 * 2 + 3` = 11. Viết đúng: `#define SQ(x) ((x) * (x))`.

### Vì sao macro nhiều lệnh nên bọc trong `do { ... } while (0)`?
- [ ] Để macro chạy nhanh hơn
- [x] Để macro dùng như một câu lệnh, an toàn sau `if` không có ngoặc nhọn và cần dấu `;`
- [ ] Để tránh tham số bị tính nhiều lần
- [ ] Bắt buộc theo chuẩn C99
> Nếu chỉ dùng `{ ... }`, viết `if (c) M(); else ...` sẽ lỗi vì `;` kết thúc if. do-while(0) biến khối thành một câu lệnh duy nhất.

### Trên máy little-endian, `uint32_t x = 0x12345678;` thì byte ở địa chỉ thấp nhất của x là?
- [ ] 0x12
- [x] 0x78
- [ ] 0x34
- [ ] 0x56
> Little-endian lưu byte thấp (LSB) ở địa chỉ thấp. Network byte order là big-endian.

### `sizeof(union U)` bằng bao nhiêu trên x86_64?
```c
union U { char c[5]; int i; };
```
- [ ] 5
- [x] 8
- [ ] 9
- [ ] 4
> Kích thước = member lớn nhất (5) làm tròn lên bội của alignment lớn nhất (4 của int) → 8.

### Kết quả `printf("%d", -1 < 1U);`?
- [ ] 1
- [x] 0
- [ ] -1
- [ ] Undefined behavior
> -1 được chuyển sang unsigned thành 4294967295, lớn hơn 1 → 0. Bẫy so sánh có dấu với không dấu.

### Biểu thức nào kiểm tra x là luỹ thừa của 2 (x là unsigned)?
- [ ] `x & (x + 1) == 0`
- [x] `x && !(x & (x - 1))`
- [ ] `(x | (x - 1)) == 0`
- [ ] `x % 2 == 0`
> Luỹ thừa của 2 có đúng một bit 1; `x & (x-1)` xoá bit 1 thấp nhất → bằng 0. Phải loại trừ x = 0.

### Cách đúng để xoá bit thứ n của `reg`?
- [ ] `reg &= (1 << n);`
- [ ] `reg |= ~(1 << n);`
- [x] `reg &= ~(1u << n);`
- [ ] `reg ^= (1 << n);`
> Set: `|= (1u << n)`, clear: `&= ~(1u << n)`, toggle: `^= (1u << n)`, đọc: `(reg >> n) & 1u`.

### Trường hợp nào là undefined behavior? (chọn tất cả đáp án đúng)
- [x] `int x = INT_MAX; x++;`
- [ ] `unsigned u = 0; u--;`
- [x] `char *s = "abc"; s[0] = 'A';`
- [x] `int i = 1; i = i++ + 1;`
> Tràn số có dấu, sửa string literal và sửa một biến hai lần không có sequence point đều là UB. Số không dấu tràn được định nghĩa là modulo 2ⁿ.

### `char s[] = "hello";` thì `sizeof(s)` và `strlen(s)` là?
- [ ] 5 và 5
- [x] 6 và 5
- [ ] 8 và 5
- [ ] 6 và 6
> Mảng chứa thêm '\0' → 6 byte, strlen không đếm '\0' → 5. Nếu là `char *s` thì sizeof là 8 (con trỏ).

### Sau `int a[5]; int *p = a;` thì `sizeof(a)` và `sizeof(p)` lần lượt là (x86_64)?
- [ ] 5 và 8
- [x] 20 và 8
- [ ] 20 và 20
- [ ] 8 và 8
> sizeof mảng thật = 5 × 4. Con trỏ luôn 8 byte, dù trỏ tới mảng.

### `realloc(p, n)` trả về con trỏ khác p. Điều gì đúng?
- [ ] Phải free(p) cũ ngay sau đó
- [x] Dữ liệu đã được copy sang vùng mới, p cũ không còn hợp lệ
- [ ] Vùng cũ vẫn dùng được song song với vùng mới
- [ ] realloc thất bại
> realloc tự copy và giải phóng vùng cũ. Nếu realloc trả NULL thì vùng cũ vẫn còn — vì vậy không viết `p = realloc(p, n)` mà không kiểm tra.

### Thứ tự các giai đoạn khi gcc biên dịch một file .c thành file chạy?
- [ ] compile → preprocess → link → assemble
- [x] preprocess → compile → assemble → link
- [ ] preprocess → assemble → compile → link
- [ ] link → preprocess → compile → assemble
> `gcc -E` (preprocess, ra .i), `-S` (compile, ra .s), `-c` (assemble, ra .o), cuối cùng link ra file thực thi.

### `int x = 5; int y = x++ * 2;` thì x và y là?
- [ ] x = 6, y = 12
- [x] x = 6, y = 10
- [ ] x = 5, y = 10
- [ ] x = 5, y = 12
> Hậu tố x++ trả giá trị cũ (5) rồi mới tăng x lên 6.

### Kết quả `printf("%d", 7 / -2);` theo chuẩn C99 trở lên?
- [ ] -4
- [x] -3
- [ ] 3
- [ ] Implementation-defined
> Từ C99, phép chia nguyên cắt về phía 0 → -3. Phần dư cùng dấu với số bị chia: `7 % -2 = 1`, `-7 % 2 = -1`.
